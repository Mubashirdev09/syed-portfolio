## The Problem

Bitcoin transaction fees changed significantly between 2013 and 2017, with a notable spike in 2017. The goal of this project was to convert raw public blockchain data into an analytics-ready pipeline that could explain when fees were lowest, when they peaked, and how transaction growth affected those changes.

## Architecture

The pipeline starts with public Bitcoin Parquet files stored on AWS S3. Raw files are ingested into Azure Data Lake Gen2 as the Bronze layer, transformed in Azure Synapse with PySpark into a cleaned Silver layer, and aggregated into a compact Gold layer for reporting. GitHub Actions triggers the workflow daily, Kafka simulates streaming transactions, Airflow manages orchestration, and the outputs are delivered through Streamlit and Power BI.

```text
AWS S3 (59 Parquet files)
  ↓
GitHub Actions trigger
  ↓
Azure Data Lake Gen2 — Bronze
  ↓
PySpark on Azure Synapse — Silver
  ↓
Gold analytics layer
  ↓
Kafka + Airflow
  ↓
Streamlit dashboard + Power BI report
```

## What I Built

- Ingested 59 Parquet files containing 8.7 million Bitcoin transactions from AWS S3.
- Implemented a Medallion Architecture with Bronze, Silver, and Gold layers in Azure Data Lake Gen2.
- Built PySpark transformations for cleaning, feature engineering, and annual aggregation in Azure Synapse.
- Added GitHub Actions automation to trigger the pipeline on a daily schedule.
- Used Kafka and Airflow to simulate streaming and orchestrate pipeline tasks.
- Published analytics outputs through a public Streamlit dashboard and a Power BI report.

## Key Decisions

This project was shaped by a few important engineering choices. I used Azure for storage and transformation to keep the analytics workflow centralized, while still ingesting from AWS S3 to demonstrate cross-cloud movement. I also adopted Medallion Architecture to preserve raw data, simplify debugging, and produce a lightweight Gold layer for dashboard performance.

Publishing both Streamlit and Power BI outputs was another deliberate choice. Streamlit made the project easy to share publicly and update in Python, while Power BI provided a more familiar BI-style interface for non-technical viewers.

## Results

- Processed 8.7 million Bitcoin transactions from raw source files.
- Reduced the final reporting dataset to a compact Gold layer for fast dashboard queries.
- Identified 2017 as the peak fee year, with average fees reaching 3.22%.
- Measured 484% transaction growth from 2013 to 2017.
- Showed that fee percentage had almost no correlation with transaction value alone, pointing instead to network congestion as the more important driver.

## What I Learned

This project reinforced the importance of designing pipelines in layers rather than transforming data directly into dashboard outputs. It also showed that technical projects become much stronger when they connect infrastructure decisions to a real analytical question and present the result in a form that non-technical users can understand.
